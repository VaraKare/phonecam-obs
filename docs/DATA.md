# Data and storage

The probe has camera permission only. It records no audio and requests no Internet access. Benchmark acquisition begins only after Record. Live acquisition requires an explicit Start USB live tap plus an authenticated local receiver. Navigation to the background stops either mode. Screen stay-awake applies only during an explicitly initiated session. Live mode has no muxer or media-file output.

Capability reports and explicitly recorded MP4/JSON pairs are stored in the app's private `files/benchmarks` directory. Incomplete captures retain a `.partial.mp4` suffix and an unsuccessful sidecar, so failed evidence cannot look complete. No automatic media expiry is promised. Delete through the app or uninstall. Android/OS logs, installation metadata and APK files are separate from benchmark media.

Host collection copies these files into `benchmarks/raw/<collection>/`; it never deletes phone files. Raw media, review copies, scoring sheets and private source mappings are gitignored. Blind review makes deliberate additional copies; the tool reports the destination. Delete those directories when finished. Benchmark reports may reveal phone model/OS and recording settings; review before publishing. No serial number is written into public reports.

USB live uses an Android abstract local socket, forwarded by ADB to a Mac loopback TCP port (chosen by ADB for the OBS source; 27183 for the command-line receiver). It does not bind a LAN address or require Android INTERNET permission. An app-private random 256-bit key authenticates the receiver before the camera opens. The app gives the key only to Android's shell user through a content provider (`content://dev.phonecam.obs.pairing/token`), which only an authorized ADB connection can use; other phone apps get nothing. The OBS source keeps the key in memory only. The command-line receiver's `tools/live.py prepare` writes it to `~/Library/Application Support/phonecam-obs/live.json` with mode 0600; do not share that file. The key persists until app data is cleared or the app is uninstalled. The trust boundary is the USB-debugging-authorized Mac: any process on that Mac that can run ADB can read the key.

Live encoded frames are bounded to 4 MiB each, with a two-frame/8 MiB application queue; configuration is bounded to 64 KiB. Kernel/ADB and OBS buffers are separate. Congestion clears queued dependencies and waits for a new keyframe. VideoToolbox decodes one submitted sample at a time; OBS receives raw NV12 through its standard RAM interface with async buffering disabled. Logs contain connection/error status, not media or authentication tokens. OBS and operating-system logging remain independently managed. Use **Stop capture**, hide/delete the OBS source, or leave/lock the phone app to stop the session. Hiding/deleting the source disconnects; starting again requires another explicit phone Start.

To remove local USB settings, delete the Mac `live.json` file and run `adb forward --remove tcp:27183` for the selected device. Remove only `~/Library/Application Support/obs-studio/plugins/phonecam-usb.plugin` to uninstall this research plugin. Existing benchmark files are independent.

Telemetry uses fixed counters and bounded timing windows, not per-frame lists. The sidecar labels its frame-gap percentile as a recent bounded sample and reports overall counts/maximum separately. Java/native heap samples do not represent total process memory or prove a two-hour stability gate.
